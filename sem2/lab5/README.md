# Лабораторная работа №5. Разработка клиента

**Цель работы:** получить практические навыки работы с Spring Framework —
разработать клиентское приложение, взаимодействующее с сервером по REST.

## 1. Теоретические сведения

Клиент-серверное приложение состоит из клиента (интерфейс пользователя) и
сервера (бизнес-логика и база данных), связанных по сети. Клиент отправляет
HTTP-запрос, сервер обрабатывает его, обращается к базе данных и возвращает
ответ в формате JSON со статусным кодом (200 OK, 201 Created, 403 Forbidden и
т. д.). REST — архитектурный подход, в котором ресурсы адресуются URL, а
операции выполняются методами HTTP (GET, POST, DELETE). Аутентификация в
работе выполнена по схеме HTTP Basic: логин и пароль передаются в заголовке
`Authorization` в кодировке Base64.

## 2. Состав работы

```
lab5/
├── server/   Spring Boot: REST-интерфейс поверх базы данных из ЛР №4
└── client/   приложение на Swing: вход, таблица задач, добавление, удаление,
              сортировка
```

Сервер использует модель данных лабораторной работы №4 (PostgreSQL, таблицы
`tasks`, `sub_tasks`, `app_users`, `task_history`, `login_history`).

## 3. REST-интерфейс сервера

| Метод | Адрес | Назначение | Права |
|---|---|---|---|
| GET | `/api/me` | логин и роли текущего пользователя | любая аутентификация |
| GET | `/api/tasks?sort=&direction=` | список задач с подзадачами | GUEST, USER, MODERATOR, ADMIN |
| GET | `/api/tasks/{id}` | одна задача | GUEST, USER, MODERATOR, ADMIN |
| POST | `/api/tasks` | создание задачи (JSON) | USER, MODERATOR, ADMIN |
| DELETE | `/api/tasks/{id}` | удаление задачи | MODERATOR, ADMIN |

Сортировка выполняется на сервере: параметр `sort` принимает значения
`created`, `priority`, `category`, `title`, `status`, `direction` — `asc` или
`desc`. Ответ содержит дополнительные данные из базы: категорию, приоритет,
время создания, автора и список подзадач:

```json
[{"id":1,"title":"Сдать лабораторную работу №4","completed":false,
  "priority":"HIGH","category":"Учеба","createdAt":"20.11.2026 18:51",
  "author":"user","subTasks":[{"id":1,"description":"Создать базу данных",
  "completed":false}]}]
```

Для REST-интерфейса включена аутентификация HTTP Basic и отключена
CSRF-защита (`csrf.ignoringRequestMatchers("/api/**")`); веб-интерфейс
продолжает работать через форму входа.

## 4. Клиентское приложение (Swing)

| Класс | Назначение |
|---|---|
| `ApiClient` | HTTP-запросы к серверу, формирование заголовка Basic, разбор JSON через Jackson |
| `ui.LoginFrame` | форма входа: адрес сервера, логин, пароль |
| `ui.MainFrame` | главное окно: таблица задач, кнопки «Обновить», «Добавить», «Удалить», выбор сортировки |
| `ui.AddTaskDialog` | диалог создания задачи (название, описание, категория, приоритет) |
| `model.TaskItem`, `model.UserInfo` | модели данных клиента |
| `ClientDemo` | консольная демонстрация обмена с сервером (без GUI) |

Таблица содержит столбцы: №, название, описание, категория, приоритет, дата
создания, автор, подзадачи, статус. Кнопка «Удалить» активна только при
наличии роли MODERATOR или ADMIN и выбранной строке; при отказе сервера
(403) пользователю выводится сообщение. Дополнительно включена сортировка
щелчком по заголовку столбца (`setAutoCreateRowSorter(true)`).

## 5. Выполнение дополнительного задания

| Требование | Реализация |
|---|---|
| Вывод дополнительных данных из БД, добавленных в прошлой работе | в ответе `/api/tasks` передаются категория, приоритет, время создания, автор и подзадачи; все они отображаются в столбцах таблицы |
| Удаление задач из клиента с правом только у определённой роли | `DELETE /api/tasks/{id}` с `@PreAuthorize("hasAnyRole('MODERATOR','ADMIN')")`; кнопка «Удалить» включается по роли из `/api/me`, сервер повторно проверяет право |
| Добавление задач из клиента | `POST /api/tasks`, диалог `AddTaskDialog`; после создания список перечитывается |
| Сортировка задач | серверная (`sort`/`direction`) и клиентская (щелчок по заголовку столбца) |
| Улучшение интерфейса | системный стиль оформления, панель инструментов, таблица с автоподбором ширины столбцов, строка состояния с числом задач, диалог подтверждения удаления, сообщения об ошибках |

## 7. Выводы

Разработано клиент-серверное приложение: серверная часть предоставляет
REST-интерфейс над базой данных PostgreSQL, клиентская — настольное
приложение на Swing. Освоены передача данных в формате JSON, аутентификация
HTTP Basic, разграничение прав на уровне методов сервера и элементов
интерфейса клиента, серверная и клиентская сортировка. Клиент корректно
обрабатывает отказы сервера: при попытке удаления без нужной роли выводится
понятное сообщение, а кнопка удаления недоступна пользователю с ролью USER.

## 8. Запуск

```bash
# сервер (требуется PostgreSQL с базой todo_db, см. ЛР №4)
cd server && mvn package && java -jar target/lab5-server-1.0.0.jar

# клиент
cd client && mvn package
java -cp "target/classes;target/lib/*" ru.belgu.cad.lab5.client.Main

# консольная проверка обмена
java -cp "target/classes;target/lib/*" ru.belgu.cad.lab5.client.ClientDemo http://localhost:8080 user password
```

Логины: `user`, `moderator`, `admin`, `guest`; пароль `password`.
