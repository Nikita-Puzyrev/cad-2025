# Лабораторная работа №2. Spring MVC

**Цель работы:** получить практические навыки работы с Spring Framework
(модуль Spring MVC, шаблонизатор Thymeleaf).

## 1. Теоретические сведения

Spring MVC реализует архитектурный шаблон «модель — представление —
контроллер»:

- **модель (Model)** — объекты данных и бизнес-логика приложения; не содержит
  кода отображения;
- **представление (View)** — пользовательский интерфейс; в работе используется
  шаблонизатор Thymeleaf, шаблоны размещаются в `src/main/resources/templates`;
- **контроллер (Controller)** — обрабатывает HTTP-запросы, обращается к модели
  и возвращает имя представления; помечается аннотацией `@Controller`.

## 2. Тема приложения

Разработано веб-приложение для управления списком задач (to-do list).
Состав классов:

| Класс | Назначение |
|---|---|
| `Task` | модель задачи: идентификатор, название, описание, статус, категория, дата создания |
| `TaskRepository` | слой доступа к данным: хранение задач и категорий в памяти |
| `TaskService` | сервисный слой: бизнес-логика работы с задачами |
| `TaskController` | контроллер: обработка запросов и выбор представления |
| `index.html` | представление: список задач, формы добавления и фильтрации |

Подключённые зависимости: `spring-boot-starter-web` (Spring MVC и встроенный
Tomcat), `spring-boot-starter-thymeleaf` (шаблонизатор),
`spring-boot-starter-test` (тесты).

## 3. Реализация

Контроллер возвращает имя шаблона `index`, передавая в модель список задач,
список категорий и выбранную категорию:

```java
@GetMapping("/")
public String index(@RequestParam(required = false) String category, Model model) {
    model.addAttribute("tasks", taskService.getTasks(category));
    model.addAttribute("categories", taskService.getCategories());
    model.addAttribute("selectedCategory", category == null ? "" : category);
    model.addAttribute("total", taskService.getAllTasks().size());
    return "index";
}
```

Операции изменения данных завершаются перенаправлением на главную страницу
(`redirect:/`), поэтому повторная отправка формы не создаёт дубликатов:

| Метод и адрес | Назначение |
|---|---|
| `GET /` | список задач, параметр `category` — фильтр |
| `POST /addTask` | добавление задачи (название, описание, категория) |
| `POST /addCategory` | добавление новой категории |
| `POST /updateTask/{id}` | изменение статуса выполнения |
| `GET /deleteTask/{id}` | удаление задачи |

Представление построено на Thymeleaf: список задач выводится циклом
`th:each`, категории — элементами выпадающего списка, статус задачи
отображается зачёркиванием через `th:classappend`.
